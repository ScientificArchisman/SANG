# Voice conversion for SANG: target-voice rendering of driving speech (evidence-graded comparison, 2022–2026)

Evidence tags used below: **[M]** = measured number from a paper table (table named); **[R]** = README / model-card / vendor claim (not independently measured); **[I]** = my inference (only in "Inferences"). Numbers from different papers are **not directly comparable**: speaker-similarity metrics differ (Resemblyzer SECS runs ~0.75–0.9; WavLM-SV SIM ~0.3–0.75; x-vector cosine ~0.9+; kNN-VC-style "EER" is *higher = better, max 50 %*, while Diff-HierVC-style ASV EER is *lower = better*), ASR models differ (Whisper-base/small/large-v3, HuBERT-CTC, Paraformer), and test sets differ. All arXiv IDs below were resolved through the arXiv/Firecrawl paper index during this session; repo licences were read from the GitHub API on 2026-09-28.

## Q1. Non-parametric / retrieval VC that scales with target data without training (kNN-VC, Phoneme Hallucinator, MKL-VC, LinearVC, successors, RVC)

### Takeaway
kNN-VC (WavLM-Large layer 6, 20 ms frames, k=4, prematched HiFi-GAN) is the only well-documented method whose quality rises monotonically with more target audio *without any training*: it is poor at 3 s (WER 43–46 %) and weak at 5–10 s (WER 11.5–32 % depending on setup), competitive at ~30–60 s, and plateaus around 5 min (≈8 min gives "very similar performance"), with state-of-the-art speaker similarity at that point (EER 37.15 % vs FreeVC 8.97 %). Its short-reference failure is fixed by training-light add-ons (Phoneme Hallucinator: WER 5.10 %, EER 44.62 % from 3 s; MKL-VC: WER 8.13 % from one 5–10 s utterance, training-free) and by 2026 learned successors (Palindromic VC, kNN-FM-VC). RVC is the practical "fine-tune + retrieval index" counterpart but needs ~10–50 min and per-speaker training.

### Cited Findings
**kNN-VC (Baas, van Niekerk, Kamper, Interspeech 2023, arXiv 2305.18975)**
- Method: WavLM-Large layer-6 features ("a single vector for every 20 ms of 16 kHz audio"); each source frame is replaced by the mean of its k=4 cosine nearest neighbours from the pooled target "matching set"; HiFi-GAN vocoder trained on *prematched* features; layer 6 chosen because later layers (22, 24) "led to worse pitch and energy reconstruction" and layer 6 is needed "for good speaker similarity and retention of the prosody information from the source utterance" — [paper §4.1](https://arxiv.org/abs/2305.18975) [M/design].
- Table 1 (LibriSpeech test-clean, ~8 min target per speaker, 7,800 conversions, Whisper-base ASR, x-vector EER where higher = better, max 50 %): Test-set topline WER 5.96 / CER 2.38 / MOS 4.24±0.07 / SIM 3.19±0.09; VQMIVC 59.46 / 37.55 / EER 2.22 / MOS 2.70 / SIM 2.09; YourTTS 11.93 / 5.51 / 25.32 / 3.53 / 2.57; FreeVC 7.61 / 3.17 / 8.97 / 4.07±0.07 / 2.38±0.11; **kNN-VC 7.36 / 2.96 / 37.15 / 4.03±0.08 / 2.91±0.11** — [arXiv 2305.18975, Table 1](https://arxiv.org/abs/2305.18975) [M].
- Data scaling (Fig. 2, dev-clean; values only plotted): "as amount of target speaker speech decreases, both the intelligibility and speaker similarity ... deteriorates"; "roughly 8 minutes per speaker gives very similar performance to only using 5 minutes"; "with limited target data (less than 30s), intelligibility and target speaker similarity decrease to a point where the more complex baselines perform better"; prematched vocoder training improves both WER and EER "regardless of the amount of target speaker data" — [arXiv 2305.18975 §5.2](https://arxiv.org/abs/2305.18975) [M, figure-only]. README: "The improvement in quality diminishes beyond 5 minutes of reference speech" — [bshall/knn-vc](https://github.com/bshall/knn-vc) [R].
- k can grow with data: "when more reference audio is available (e.g. ≥10 mins), the conversion quality may even be improved by using larger values of k (in the order of k = 20)" — [arXiv 2305.18975 §4.1](https://arxiv.org/abs/2305.18975) [R-in-paper, preliminary].
- Compute: "inference with 8 minutes of reference audio on a consumer 8GB VRAM GPU is faster than real-time" — [arXiv 2305.18975 §4.1](https://arxiv.org/abs/2305.18975) [M, no RTF given].
- Additional points on the data-vs-quality curve from other papers (different eval setups): **3 s** target: kNN-VC WER 45.92 %, CER 27.55 %, EER 19.19 %, MOS 2.34±0.17 — [Phoneme Hallucinator Table 1](https://arxiv.org/abs/2308.06382) [M]; **single 5–10 s utterance**: WER 32.292, CER 18.877, x-vector SIM 97.219 — [MKL-VC Table 2](https://arxiv.org/abs/2506.09709) [M]; **1 min** ("1 min speech kNN-VC topline", LibriSpeech): WER 7.73, CER 3.09, EER 35.05 — [arXiv 2310.08104 Table 5](https://arxiv.org/abs/2310.08104) [M]; **3 / 10 / 30 / 60 s** prompts (English, Redimnet SIM, Whisper-large-v3): SIM 0.380 / 0.552 / 0.617 / 0.631, WER 0.430 / 0.115 / 0.042 / 0.046, MOS 1.182 / 2.588 / 3.500 / 3.000 — [Palindromic VC Table 1, arXiv 2606.08843](https://arxiv.org/abs/2606.08843) [M].
- The HLTCOE VoicePrivacy-2024 kNN-VC setup used target pools "totalling at least 55 minutes" — [arXiv 2409.08913 §2.1](https://arxiv.org/abs/2409.08913) [R-in-paper].
- Licence: MIT (LICENSE file, © 2023 MediaLab, Stellenbosch University) — [bshall/knn-vc](https://github.com/bshall/knn-vc) [R].

**Phoneme Hallucinator (Shan et al., AAAI 2024, arXiv 2308.06382)** — set-expansion model (19.03 M params, Set-Transformer conditional VAE) that hallucinates extra WavLM-L6 target vectors from a short clip, then runs kNN-VC with the kNN-VC prematched HiFi-GAN.
- Table 1 (3 s of target speech, LibriSpeech test-clean, 39,000 conversions): Oracle WER 3.47 %, CER 1.42 %, MOS 4.27±0.10, SIM 3.25±0.09; YourTTS 8.65 / 3.36 / EER 38.23 / 3.41 / 2.71; kNN-VC 45.92 / 27.55 / 19.19 / 2.34 / 2.48; FreeVC 5.40 / 2.27 / 35.63 / 4.05 / 2.62; **Phoneme Hallucinator 5.10 / 2.02 / 44.62 / 4.02±0.08 / 2.98±0.12** — [arXiv 2308.06382 Table 1](https://arxiv.org/abs/2308.06382) [M].
- Table 2 (number of hallucinated vectors): 5k → WER 6.14 / EER 49.1; 10k → 5.62 / 47.2; 15k → 5.35 / 46.2; 20k → 5.24 / 44.4; 30k → 5.10 / 44.6; 50k → 4.84 / 43.3 (more vectors = more intelligible but "biases the converted speech towards the source") — [arXiv 2308.06382 Table 2](https://arxiv.org/abs/2308.06382) [M]. WER stays "around 5%" for target durations from 1 s to 10 s (Fig. 1) [M, figure].
- Cost: hallucinating 30,000 vectors (~10 min of speech) takes 1.48 s on an RTX 4090; training 6.5 h on one RTX 4090; cross-lingual conversion shown only as audio examples — [arXiv 2308.06382 §4](https://arxiv.org/abs/2308.06382) [M/R]. Code: [PhonemeHallucinator/Phoneme_Hallucinator](https://github.com/PhonemeHallucinator/Phoneme_Hallucinator) — GitHub API reports no licence [R].

**MKL-VC (Lobashev et al., arXiv 2506.09709, 2025)** — training-free: replaces kNN with a factorised Monge–Kantorovich linear optimal-transport map in WavLM subspaces.
- Table 2 (single 5–10 s reference utterance, LibriSpeech test-clean, Whisper-base, x-vector SIM %): MKL K=2 WER 8.131 / CER 3.846 / SIM 94.579; FACodec 8.488 / 3.897 / 94.981; FreeVC 9.061 / 4.263 / 94.795; MKL K=64 12.744 / 7.213 / 96.318; Diff-VC 16.502 / 8.731 / 89.461; kNN-VC 32.292 / 18.877 / 97.219 — [arXiv 2506.09709 Table 2](https://arxiv.org/abs/2506.09709) [M]. K trades intelligibility for similarity.
- Table 3 (cross-lingual German↔French, FLEURS, ~10 s refs): FACodec WER 36.659 / CER 15.354 / SIM 95.759; MKL K=2 39.168 / 19.696 / 94.793; FreeVC-s 43.688 / 19.449 / 94.598; kNN-VC 96.662 / 63.340 / 96.520 — [arXiv 2506.09709 Table 3](https://arxiv.org/abs/2506.09709) [M].
- Claim: kNN-VC "tends to introduce language-specific pronunciation from a reference audio into a source utterance" (e.g. rolled vs guttural /r/) — [arXiv 2506.09709 §1](https://arxiv.org/abs/2506.09709) [R-in-paper, qualitative]. Code [alobashev/mkl-vc](https://github.com/alobashev/mkl-vc): GitHub API reports no licence [R].

**kDOT (arXiv 2505.04382)**: discrete-OT barycentric projection instead of kNN averaging; "often outperforms averaging-based approaches in terms of WER, MOS, and FAD" on LibriSpeech — [arXiv 2505.04382 abstract](https://arxiv.org/abs/2505.04382) [M, numbers not extracted].

**kNN-FM-VC (arXiv 2609.27230, Sept 2026)** — 13.26 M-param conditional flow-matching net trained to imitate kNN-VC transport in WavLM space; one-step inference. Table 1 (LibriSpeech test; speaker conditioning from a 200-frame target crop): one-step Gaussian Bridge WER 23 [23,24] %, UTMOSv2 3.12, target SIM 0.29; kNN WER 50, UTMOSv2 2.50, SIM 0.48; kDOT 48 / 2.51 / 0.51; MKL 72 / 2.36 / 0.27; FreeVC 24 / 2.86 / 0.28; Phoneme Hallucinator 25 / 2.86 / 0.36 — [arXiv 2609.27230 Table 1](https://arxiv.org/abs/2609.27230) [M]. Authors note "kNN and kDOT achieve the highest SIM despite substantially worse WER" [M]. (Absolute WERs are far higher than in other papers—setup not directly comparable.)

**Palindromic zero-shot VC (arXiv 2606.08843, June 2026)** — uses kNN-VC retrieval to synthesise pseudo-parallel pairs, trains a 77 M-param WavLM-L6 latent converter + HiFi-GAN with a speaker-verification loss; trained on ~3 k h English only. Table 1 (English; 3/10/30/60 s prompts): SIM 0.612 / 0.713 / 0.717 / 0.712, WER 0.056 / 0.049 / 0.047 / 0.050 vs Seed-VC SIM 0.455 / 0.578 / 0.622 / 0.630, WER 0.041 / 0.042 / 0.026 / 0.033 — [arXiv 2606.08843 Table 1](https://arxiv.org/abs/2606.08843) [M]. "No fine-tuning was performed on non-English data" yet WER improved across 7 other MLS languages (Fig. 2) [M, figure]. Note its similarity saturates by ~10 s (no further gain to 60 s) [M].

**LinearVC (Kamper, van Niekerk, Zaïdi, Carbonneau, arXiv 2506.01510, 2025)** — a single linear projection of WavLM features per (source, target) speaker pair; a rank-100 content-factorised variant.
- Table 1 (LibriSpeech test-clean, Whisper-small; MUSHRA-style subjective %): GT WER 4.3 / CER 2.3; kNN-VC 5.7 / 2.9 / EER 38.9 / Natural 60.6±3.6 / Similarity 67.2±2.7; FreeVC 5.7 / 3.0 / 10.5 / 71.1±3.6 / 48.7±2.9; SoundStorm 4.6 / 2.4 / 30.2 / 58.6±4.0 / 68.6±3.2; **LinearVC 4.9 / 2.6 / 33.6 / 62.5±3.5 / 67.5±2.6**; LinearVC factorised 4.7 / 2.5 / 35.2 / 62.3±3.7 / 64.2±3.1 — [arXiv 2506.01510 Table 1](https://arxiv.org/abs/2506.01510) [M]. Rotation alone (orthogonal W) already gives EER 27.7 % (Table 2) [M].
- Data: README says for non-parallel data "3 minutes per speaker is good, more than that doesn't help much"; the projection is learned from *both* source- and target-speaker data — [kamperh/linearvc](https://github.com/kamperh/linearvc) [R]. MIT licence [R].
- Follow-up SSL-GMMVC (arXiv 2606.10317) replaces the single linear map with GMM-weighted local affine maps and "improves speaker similarity with comparable intelligibility" — [abstract](https://arxiv.org/abs/2606.10317) [M, numbers not extracted].

**RVC (Retrieval-based Voice Conversion WebUI)** — ContentVec/HuBERT features + RMVPE F0 + per-speaker fine-tuned VITS, with a feature index: "Reduce tone leakage by replacing the source feature to training-set feature using top1 retrieval"; ">=10min low noise speech recommended"; real-time end-to-end latency "170ms", "90ms" with ASIO — [RVC README (en)](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/README.en.md) [R]. FAQ: "A dataset of around 10min to 50min is recommended"; high-quality distinctive voices "5min to 10min is fine"; 1–2 min successes "not reproducible"; poor/noisy data "20-30 epochs are sufficient", high-quality data "200 is acceptable"; index rate 1 → "theoretically there is no timbre leakage from the inference source" — [RVC FAQ](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/faq_en.md) [R]. MIT licence, ~38.6 k stars, active (last push 2026-08) — [GitHub](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI) [R].
- Only independent measurement found: per-character RVCv2-f0-48k (trained per singer) vs zero-shot Seed-VC on M4Singer singing: F0CORR 0.9404 vs 0.9375, F0RMSE 30.43 vs 33.35, SECS 0.7264 vs 0.7405, CER 28.46 vs 19.70 — [Seed-VC paper Table 2](https://arxiv.org/abs/2411.09943) [M].

### Inferences
- [I] For SANG specifically, kNN-VC is unusually well matched: it runs on the *same* WavLM-Large model SANG already uses, at the same 50 Hz frame grid (20 ms), so the source's WavLM pass can be shared and the converted audio is frame-aligned to the source by construction.
- [I] Practical data tiers for the kNN family: <10 s → do not use plain kNN-VC (WER 11.5–46 % across papers); use Phoneme Hallucinator/MKL-VC expansion or a zero-shot model; ~30–60 s → plain kNN-VC is roughly on par with zero-shot DiT models (Palindromic Table 1); ≥5 min → kNN-VC plateaus near its best, consider k≈10–20 and a larger vocoder or a fine-tuned model if more quality is needed.
- [I] LinearVC is less suitable as SANG's main path because it needs minutes of *source*-speaker data too, and SANG's driving speaker is arbitrary (often one clip).
- [I] RVC is a mature, permissive fallback for the "tens of minutes to hours" tier, but it is a per-speaker training job (minutes–hours of GPU time; not documented precisely) and its published evidence is mostly community/README-level.

### Gaps
- Exact numeric values of kNN-VC Fig. 2 (WER/EER at 5 s, 10 s, 30 s, 1 min, 5 min, 8 min on dev-clean) are only plotted; I could not extract numbers.
- No peer-reviewed quality-vs-minutes curve for RVC; RVC training time per data amount is not documented in the README/FAQ.
- Palindromic VC code/licence availability not confirmed. Phoneme Hallucinator, MKL-VC have no licence file (default "all rights reserved").

## Q2. Zero-shot VC with a short reference: Seed-VC, OpenVoice v2, FreeVC, Vevo/Vevo2, CosyVoice VC, StableVC, SEF-VC, FACodec, Diff-HierVC, DDDM-VC, GenVC, MeanVC, RT-VC, REF-VC and 2025–2026 SOTA

### Takeaway
No single public benchmark evaluates all of these under one protocol; the closest cross-model tables are Seed-VC (vs OpenVoice, CosyVoice), Vevo (vs FACodec, HierSpeech++, LM-VC, UniAudio), StableVC (vs DDDM-VC, SEF-VC, NS2VC, LM-VC), StyleStream (vs FACodec, CosyVoice 2, Seed-VC v2, Vevo, Vevo 1.5), X-VC (vs Seed-VC small/tiny, MeanVC), REF-VC and MeanVC (vs Seed-VC), and Palindromic (vs Seed-VC, Vevo, kNN-VC, OO-VC across prompt lengths). Across these, Seed-VC (v1) is consistently a strong open baseline on intelligibility and similarity; Vevo-Timbre is best at preserving source prosody; newer 2025–2026 systems (StableVC, X-VC, StyleStream, Palindromic) beat Seed-VC on specific metrics but have weaker code/licence situations.

**SEF-VC (arXiv 2312.08676)** — speaker-embedding-free cross-attention to reference, NAR reconstruction from HuBERT semantic tokens; better "even for very short reference speeches" — [abstract](https://arxiv.org/abs/2312.08676) [R-in-paper]; numbers above via StableVC [M].

**FACodec (NaturalSpeech 3 codec)** — factorises content / prosody / timbre / acoustic details; VC by swapping the timbre embedding; 16 kHz, hop 200; weights Apache-2.0 — [huggingface.co/amphion/naturalspeech3_facodec](https://huggingface.co/amphion/naturalspeech3_facodec) [R]. Measured: best intelligibility among MKL-VC baselines on short refs (WER 8.488) and best cross-lingual de↔fr (WER 36.659) [MKL-VC Tables 2–3](https://arxiv.org/abs/2506.09709); low naturalness in Vevo (N-MOS 2.50) and StyleStream (NMOS 2.55) evaluations [M]; human raters described "distortions (robotic voice)" for Sakha [MKL-VC Table 4](https://arxiv.org/abs/2506.09709) [M, n=6 raters].

**Diff-HierVC (arXiv 2311.04693) / DDDM-VC (arXiv 2305.15816)** — diffusion VC with explicit target-style F0 generation (DiffPitch) and source-filter disentanglement; Diff-HierVC reports "CER of 0.83% and EER of 3.29% in zero-shot VC" (ASV EER, *lower is better* here) — [abstract](https://arxiv.org/abs/2311.04693) [M]. DDDM-VC numbers via StableVC above. GitHub repos (hayeong0/Diff-HierVC, hayeong0/DDDM-VC) have no licence per GitHub API [R].

**GenVC (arXiv 2502.04519)** — AR LM on ContentVec-derived tokens, self-supervised; Table II (EMIME, WavLM-base-sv SIM, UTMOSv2): YourTTS 0.885 / 2.43; FreeVC 0.878 / 2.81; Neural VC 0.881 / 2.60; GenVC-Small 0.869 / 2.66; GenVC-Large 0.884 / 2.65. Table III: NMOS FreeVC 3.96 vs GenVC-S 3.57; SMOS GenVC-S 3.72 vs FreeVC 3.48 — [arXiv 2502.04519](https://arxiv.org/abs/2502.04519) [M]. Its AR formulation "introduces flexibility in temporal alignment, reducing the preservation of source prosody" [R-in-paper].

**MeanVC (arXiv 2510.08392; Apache-2.0)** — 14 M-param streaming DiT with mean flows (1 NFE), Chinese streaming-ASR bottleneck features. Table 1 (zero-shot, Chinese; single AMD EPYC core): StreamVoice CER 9.32 / SSIM 0.543 / RTF 13.632 / latency 2,379.52 ms; Seed-VC 6.03 / 0.582 / 7.039 / 1,990.72 ms; **MeanVC 5.01 / 0.687 / 0.136 / 211.52 ms** (NMOS 3.82, SMOS 3.87); full pipeline RTF 0.322 — [arXiv 2510.08392](https://arxiv.org/abs/2510.08392) [M]; licence [ASLP-lab/MeanVC](https://github.com/ASLP-lab/MeanVC) [R]. "its content encoder module only supports Chinese" — [X-VC §4.3](https://arxiv.org/abs/2604.12456) [R-in-paper]. **MeanVC 2 (arXiv 2606.09050)**: latency 211 → 110 ms, 40 ms chunks, timbre encoder robust to low-quality references; "source code will be publicly released" — [abstract](https://arxiv.org/abs/2606.09050) [R-in-paper].

**RT-VC (arXiv 2506.10289)** — articulatory-feature (SPARC) VC with DDSP vocoder; "CPU latency of 61.4 ms", quality "comparable to the current state-of-the-art" — [abstract](https://arxiv.org/abs/2506.10289) [M, detailed numbers not extracted].

**REF-VC (arXiv 2508.04996, ASRU 2025)** — noise-robust expressive DiT (BNF + randomly-erased WavLM features, E2-TTS-style implicit alignment, 4-step shortcut sampling; 100 M params; Emilia 100 k h). Clean set: REF-VC (32 NFE) NMOS 3.92 / SMOS 3.98 / CER 5.34 / SECS 0.8253 vs Seed-VC 3.87 / 4.03 / 5.16 / 0.8226; noisy set: REF-VC 3.68 / 3.84 / **8.03** / 0.8031 vs Seed-VC 3.76 / 3.75 / 12.45 / 0.7884; REF-VC 4 NFE clean CER 5.53, SECS 0.8075 — [arXiv 2508.04996 Table I](https://arxiv.org/abs/2508.04996) [M]. Limitation: "our model cannot generate arbitrarily long speech" due to implicit alignment [R-in-paper]. No public code found.

**X-VC (arXiv 2604.12456, 2026; MIT)** — one-step conversion in SAC-codec latent space; offline en WER 2.83 / SIM 0.63 / UTMOS 3.31, zh 1.99 / 0.73 / 2.69, **RTF 0.014** (RTX 3090); SMOS 3.98±0.10 (en) vs Seed-VC 3.56±0.12 — [arXiv 2604.12456 Tables 2–3](https://arxiv.org/abs/2604.12456) [M]; trained on ~10 k h en+zh plus ~20 k h Seed-VC-generated pairs [R-in-paper]; code [Jerrister/X-VC](https://github.com/Jerrister/X-VC) MIT [R].

**Other 2025–2026 zero-shot systems (abstract-level only)**: MaskVCT (arXiv 2509.17143) "achieves the best target speaker and accent similarities" and can omit pitch contour to control prosody; R-VC (arXiv 2506.01014) transfers target *rhythm* via duration modelling; EZ-VC (arXiv 2505.16691) discrete-SSL + DiT, "excel[s] in zero-shot cross-lingual settings even for unseen languages"; OneVoice (arXiv 2601.18094) unified linguistic/expressive/singing VC with 2-step decoding; VoicePrompter (arXiv 2501.17612); AdaptVC (arXiv 2501.01347); OO-VC (arXiv 2510.09061, "16.35% relative reduction in word error rate and a 5.91% improvement in speaker cosine similarity") — [MaskVCT](https://arxiv.org/abs/2509.17143), [R-VC](https://arxiv.org/abs/2506.01014), [EZ-VC](https://arxiv.org/abs/2505.16691), [OneVoice](https://arxiv.org/abs/2601.18094), [OO-VC](https://arxiv.org/abs/2510.09061) [R-in-paper].

**Chatterbox VC (Resemble AI; MIT)** — `ChatterboxVC.generate` tokenises the source with S3Tokenizer and runs `s3gen.inference(speech_tokens=s3_tokens, ref_dict=...)`; reference truncated to `DEC_COND_LEN`; "No explicit source audio length modification"; output watermarked with Perth — [vc.py](https://github.com/resemble-ai/chatterbox/blob/master/src/chatterbox/vc.py) [R, code reading]. Multilingual V3 (TTS) "23+" languages — [resemble-ai/chatterbox](https://github.com/resemble-ai/chatterbox) [R]. No published VC metrics found.

### Inferences
- [I] On like-for-like tables Seed-VC v1 ≈ best open offline zero-shot VC of 2024–25 on WER/SECS; 2026 systems (X-VC, StyleStream, Palindromic) report gains but are younger, less battle-tested, and (except X-VC, MIT) have unclear code availability.
- [I] Diffusion/flow models built on continuous content features (Seed-VC, REF-VC, StableVC) generally beat discrete-token LM VC (LM-VC, UniAudio, GenVC) on WER; LM/AR VC buys speaker/style similarity at the cost of intelligibility and timing control.
- [I] "Zero-shot" similarity numbers from Resemblyzer (0.82–0.87) look much higher than WavLM-SV numbers (0.4–0.73) for the same Seed-VC model — never compare SECS across papers.

### Gaps
- I did not find a VC-specific leaderboard/benchmark that covers the requested set (no "VCBench"/"VoxSim"-style unified VC table was located; RVCBench, arXiv 2602.00443, evaluates 18 open-source *voice-cloning/TTS* models, not VC).
- No independent metrics for Chatterbox VC, OpenVoice v2 multilingual VC, or CosyVoice 2/3 in an official VC mode; RT-VC and SEF-VC code availability not verified.
- Vevo training-data description conflicts between paper (60 K h audiobook) and HF card (Emilia 101 k h).

## Q3. Does the output preserve source duration / frame timing? (critical for SANG lip-sync)

### Takeaway
Frame-synchronous by construction: kNN-VC and all WavLM-matching variants (Phoneme Hallucinator, MKL-VC, kDOT, kNN-FM-VC, LinearVC), RVC/so-vits-svc, FreeVC, FACodec, Vevo-Timbre, Seed-VC v1 (and v2 with `convert-style=false`) at `length_adjust=1.0`, Chatterbox VC, X-VC, MeanVC and StyleStream (explicitly stated only for kNN-VC, Seed-VC's length_adjust, StyleStream and Chatterbox's code; for the others it follows from their published architectures — see Inferences). Timing is *regenerated* (lip-sync drift risk) in AR/duration-model systems: Vevo-Voice/Vevo-Style/Vevo 1.5/Vevo2, Seed-VC v2 with `convert-style=true`, GenVC, StableVC (duration module), R-VC (rhythm transfer), LM-VC/UniAudio-style codec LMs. Only kNN-family methods operate on exactly SANG's 20 ms WavLM grid.

### Cited Findings
- kNN-VC: "replace each frame of the source representation with its nearest neighbor in the reference", then vocode — one output frame per 20 ms source frame — [arXiv 2305.18975](https://arxiv.org/abs/2305.18975) [M/design]. Same construction in Phoneme Hallucinator (kNN after set expansion) [arXiv 2308.06382](https://arxiv.org/abs/2308.06382), MKL-VC (per-frame OT map) [arXiv 2506.09709](https://arxiv.org/abs/2506.09709), LinearVC (per-frame linear projection) [arXiv 2506.01510](https://arxiv.org/abs/2506.01510) [design].
- Private kNN-VC had to *add* a phone-duration predictor to change timing, confirming vanilla kNN-VC keeps source phone durations; source phone durations "encode speaker identity" (EER 10 % → up to 22.5 % when durations are anonymised) — [arXiv 2505.17584](https://arxiv.org/abs/2505.17584) [M].
- Seed-VC: `length-adjust` default "1.0"; "<1.0 for speed-up speech, >1.0 for slow-down speech"; v2 `convert-style` true "use[s] AR model for accent & emotion conversion", false conducts "only timbre conversion similar to V1" — [seed-vc README](https://github.com/Plachtaa/seed-vc) [R].
- Vevo: content tokens use "duration reduction ... to further remove some style patterns such as unit-level duration"; Vevo-Voice uses the AR ℳ_style stage, Vevo-Timbre only flow matching — [arXiv 2502.07243 §1, §4.2](https://arxiv.org/abs/2502.07243) [design].
- StableVC: "The duration module is trained to re-predict the duration ... This enables the generated waveform to adapt different durations based on the different timbre and style" — [arXiv 2412.04724](https://arxiv.org/abs/2412.04724) [design].
- GenVC: AR formulation "introduces flexibility in temporal alignment" — [arXiv 2502.04519](https://arxiv.org/abs/2502.04519) [design]. R-VC "adapts the linguistic content duration to the desired target speaking style" — [arXiv 2506.01014](https://arxiv.org/abs/2506.01014) [design].
- StyleStream: "the non-autoregressive, streaming-oriented design preserves the source utterance duration" — [arXiv 2602.20113 §6.3.3](https://arxiv.org/abs/2602.20113) [design].
- Chatterbox VC: no explicit source-length modification in `ChatterboxVC.generate` — [vc.py](https://github.com/resemble-ai/chatterbox/blob/master/src/chatterbox/vc.py) [R].
- REF-VC uses E2-TTS-style "implicit alignment" and notes it "cannot generate arbitrarily long speech" — [arXiv 2508.04996](https://arxiv.org/abs/2508.04996) [design].
- RVC uses ContentVec features + source F0 (RMVPE) with top-1 index retrieval of training features — [RVC README](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/README.en.md) [design].

### Inferences
- [I] For Seed-VC v1, CosyVoice-300M VC (25 Hz tokens → flow matching), Chatterbox VC (S3 tokens → S3Gen), FreeVC/RVC (frame features → VITS), FACodec (80 Hz codes) and X-VC (62.5 Hz codec latents), total duration equals the source and alignment is at the model's own frame rate (20–40 ms). This is "duration-preserving" but, unlike kNN-VC, frame alignment to SANG's 20 ms WavLM grid is only approximate (resampling/interpolation of content features); residual offsets should be ≤ 1 model frame, but I found no measurement of this.
- [I] REF-VC's implicit alignment preserves *total* length but not guaranteed per-frame alignment — treat as drift-risk until measured.
- [I] Validation recipe for SANG: run WavLM-Large on source and converted audio, compute a DTW path over (e.g. layer-6 or PPG) features and report mean |path − diagonal| in frames; accept a VC only if ≤1 frame (20 ms) on average; also run SyncNet/LSE-D on the rendered video from source-driven vs converted-driven motion.
- [I] Because frame-synchronous VC keeps source rhythm, SANG can generate face motion from the *source* audio and dub the converted audio without drift; with kNN-VC it can even reuse the source WavLM pass.

### Gaps
- No paper measures frame-level alignment error (e.g. DTW deviation) between source and converted audio for Seed-VC, CosyVoice VC, Chatterbox VC, OpenVoice or X-VC.
- OpenVoice's tone-colour converter and SEF-VC timing behaviour are inferred from architecture descriptions, not verified in code.

## Q4. How does quality scale with the amount of target-speaker data (seconds → minutes → hours), and which adaptation paths exist?

### Takeaway
Three regimes are documented: (1) **seconds** — zero-shot DiT/flow models (Seed-VC, Vevo, StableVC) or kNN-set expansion (Phoneme Hallucinator, MKL-VC) dominate; plain kNN-VC is unusable below ~10 s; (2) **~30 s to ~5 min** — kNN-VC catches up with and passes zero-shot models on speaker similarity with zero training, plateauing near 5 min; zero-shot models' similarity saturates by ~30 s (Seed-VC SIM 0.622 → 0.630 from 30 → 60 s; Palindromic ~flat after 10 s); (3) **tens of minutes to hours** — only per-speaker fine-tuning (Seed-VC fine-tune, RVC, so-vits-svc, MeanVC tuning) keeps improving, but no peer-reviewed quality-vs-minutes curve exists for modern VC fine-tuning.

### Cited Findings
- Zero-shot models saturate early: Seed-VC SIM 0.455 / 0.578 / 0.622 / 0.630 and Vevo 0.510 / 0.639 / 0.651 / 0.332 for 3 / 10 / 30 / 60 s prompts; Palindromic 0.612 / 0.713 / 0.717 / 0.712 — [arXiv 2606.08843 Table 1](https://arxiv.org/abs/2606.08843) [M]. Seed-VC "without full reference enrollment" (embedding only) drops SECS 0.8676 → 0.7948, i.e. in-context reference length matters — [arXiv 2411.09943 Table 1](https://arxiv.org/abs/2411.09943) [M].
- kNN-VC keeps improving to ~5 min: WER 45.92 % (3 s) → 32.29 % (5–10 s) → 7.73 % (1 min) → 7.36 % (~8 min); EER 19.19 % (3 s) → 35.05 % (1 min) → 37.15 % (8 min) — from [Phoneme Hallucinator T1](https://arxiv.org/abs/2308.06382), [MKL-VC T2](https://arxiv.org/abs/2506.09709), [arXiv 2310.08104 T5](https://arxiv.org/abs/2310.08104), [kNN-VC T1](https://arxiv.org/abs/2305.18975) [M, heterogeneous setups]; plateau "beyond 5 minutes" [README](https://github.com/bshall/knn-vc) [R].
- Seed-VC fine-tuning: "minimum 1 utterance per speaker", "minimum 100 steps, 2 min on T4", files of "1 to 30 seconds", multi-speaker fine-tuning supported — [seed-vc README](https://github.com/Plachtaa/seed-vc) [R]. No published fine-tuned-vs-zero-shot numbers found.
- MeanVC fine-tuning on 4 Aishell3 speakers: clean CER 3.33 → 3.09, SSIM 0.681 → 0.696, DNSMOS 3.69 → 3.74; noisy input CER 12.84 → 10.81, SSIM 0.633 → 0.657 (amount of tuning data not stated) — [arXiv 2510.08392 Table 2](https://arxiv.org/abs/2510.08392) [M].
- RVC: 10–50 min recommended, 5–10 min acceptable for clean distinctive voices, 1–2 min "not reproducible" — [RVC FAQ](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/faq_en.md) [R].
- so-vits-svc: AGPL-3.0 and archived — [GitHub](https://github.com/svc-develop-team/so-vits-svc) [R]; its 4.0 per-speaker model lost to zero-shot Seed-VC on one character (SECS 0.8637 vs 0.8899; CER 9.63 vs 4.66) — [EVAL.md](https://github.com/Plachtaa/seed-vc/blob/main/EVAL.md) [M, n=1 speaker].
- TTS context only: GPT-SoVITS claims "5-second" zero-shot and "Fine-tune the model with just 1 minute of training data", languages en/ja/ko/yue/zh, MIT — [RVC-Boss/GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) [R]. Voice Filter (TTS + VC post-module) works "on one minute of speech" and is "competitive against a TTS model built on 30 times more data" — [arXiv 2202.08164](https://arxiv.org/abs/2202.08164) [M]. SVCC 2023 gave 150–160 target utterances for fine-tuning, and a model pre-trained on 750 h then fine-tuned per target was competitive — [arXiv 2310.05203](https://arxiv.org/abs/2310.05203) [M].

### Inferences
- [I] A tiered SANG pipeline follows directly: 0 s (no X audio) → no conversion or a consented stock voice; 3–30 s → zero-shot (Seed-VC-class) or kNN + set expansion; 30 s–5 min → kNN-VC with the full matching set (k=4, rising to ~10–20 at ≥10 min); ≥10–30 min → optional fine-tuned model (Seed-VC fine-tune or RVC) evaluated against kNN-VC on a held-out clip.
- [I] kNN-VC's matching set is the cheapest way to make quality "keep improving as data arrives": appending new clean frames needs only a WavLM forward pass; storage ≈ 50 × 1024 floats per second (≈12 MB/min fp32, ≈6 MB/min fp16) — compute from the stated 20 ms/1024-d feature rate.

### Gaps
- No published curve of Seed-VC/RVC/so-vits-svc quality vs minutes of fine-tuning data; no study of when fine-tuning overtakes kNN-VC with the same data.
- kNN-VC behaviour beyond ~8 min per speaker (hours) is not reported beyond the "k≈20" remark.

## Q5. Prosody / emotion preservation and accent handling

### Takeaway
For SANG (keep the driving performance's emotion and timing, change only timbre), "timbre-only" methods are the right class: kNN-VC keeps source prosody (layer 6 chosen for it; VoicePrivacy emotion UAR 56.70 % vs 30.35 % for an ASR-TTS cascade) and Vevo-Timbre has the best measured source-F0 correlation (FPC 0.686). Seed-VC v1 keeps timing but tends to pull intonation toward the *reference* prompt. Methods that convert accent/emotion to the target (Vevo-Voice, Seed-VC v2 `convert-style`, StyleStream, MaskVCT) regenerate timing and should be optional. kNN-VC may leak target-language pronunciation in cross-lingual use.

### Cited Findings
- kNN-VC layer-6 choice is "necessary for good speaker similarity and retention of the prosody information from the source utterance" — [arXiv 2305.18975 §4.1](https://arxiv.org/abs/2305.18975) [R-in-paper].
- VoicePrivacy 2024 (IEMOCAP emotion UAR, higher = better emotion preserved): original speech UAR 70.07 %; kNN-VC 56.70 % (WER 3.162 %); Whisper-VITS ASR→TTS cascade 30.35 % — [HLTCOE, arXiv 2409.08913 Table 1](https://arxiv.org/abs/2409.08913) [M]. "voice conversion systems better preserve emotional content" [R-in-paper].
- Vevo Table 3: FPC (F0 correlation with source) Vevo-Timbre 0.686, HierSpeech++ 0.634, FACodec 0.611, UniAudio 0.575, LM-VC 0.524, Vevo-Voice 0.485; PS-MOS (prosody similarity to source) Vevo-Timbre 3.45, FACodec 3.10, HierSpeech++ 3.08, Vevo-Voice 2.60 — [arXiv 2502.07243](https://arxiv.org/abs/2502.07243) [M].
- Seed-VC prosody: "Seed-VC's conversion results exhibit high consistency with the prosody of the prompt audio from the target speaker, and its prosodic stability decreases when the prompt audio contains distinctive stylistic characteristics"; REF-VC wins an ABX test on prosody reconstruction — [arXiv 2508.04996 §IV-A](https://arxiv.org/abs/2508.04996) [M, ABX figure]. Palindromic authors: Seed-VC demo examples "indicate challenges in preserving source prosody" — [arXiv 2606.08843](https://arxiv.org/abs/2606.08843) [R-in-paper, qualitative].
- Accent/emotion *conversion to target*: Vevo-Voice A-SIM 0.614 / E-SIM 0.872 / AS-MOS 3.90 vs Vevo-Timbre 0.567 / 0.816 / 3.55 — [arXiv 2502.07243](https://arxiv.org/abs/2502.07243) [M]; StyleStream offline A-SIM 0.640 / E-SIM 0.827 vs Vevo 0.596 / 0.712, SeedVC v2 0.549 / 0.688, CosyVoice 2.0 0.450 / 0.655 — [arXiv 2602.20113 Table 1](https://arxiv.org/abs/2602.20113) [M]; MaskVCT "best target speaker and accent similarities" — [arXiv 2509.17143](https://arxiv.org/abs/2509.17143) [R-in-paper].
- Emotion-aware VC research lines: prosody embeddings from an emotion-recognition model restore source prosody in an ICL flow-matching VC (evaluated on ESD) — [arXiv 2409.05004](https://arxiv.org/abs/2409.05004); SSL features + speaker embedding vocoder "keep[s] the prosody and content of the source speaker" — [arXiv 2505.08278](https://arxiv.org/abs/2505.08278); expressive NAR VC with multilingual discrete units and local F0 cross-attention — [arXiv 2506.04013](https://arxiv.org/abs/2506.04013) [R-in-paper, abstracts].
- Cross-lingual accent leakage in kNN-VC (reference-language phones, e.g. /r/) — [arXiv 2506.09709 §1](https://arxiv.org/abs/2506.09709) [R-in-paper]; kNN-VC with stuttered references copies non-fluent units (FreeVC W/CER "less than half" of kNN-VC's) — [arXiv 2310.08104 §3](https://arxiv.org/abs/2310.08104) [M].

### Inferences
- [I] kNN-VC can only output frames that exist in the matching set: if X's clean audio is all calm/neutral, highly emotional source frames (shouting, laughter, crying) will be matched to the nearest *neutral* frames, flattening emotion; F0 itself is partly carried in layer-6 features but range is limited by what X ever produced. Collecting varied-emotion target audio directly improves emotional range — this is the kNN analogue of "more data helps".
- [I] Pitch register: frame-synchronous VCs that copy source F0 (RVC, Seed-VC singing with F0) need a global pitch shift (source median F0 → target median F0) for cross-gender conversion; kNN-VC/Seed-VC v1 speech handle this implicitly.
- [I] Whether SANG should keep the *driver's* accent or adopt X's accent is a product decision; keeping timing favours timbre-only VC (accent retained), while accent adoption requires AR style models that break frame sync.

### Gaps
- No direct emotion-preservation metric (e.g. emotion2vec similarity to source) reported for Seed-VC v1, kNN-VC vs matching-set emotional coverage, or RVC.

## Q6. Multilingual and cross-lingual support (~15 languages)

### Takeaway
No method is benchmarked on ~15 languages. WavLM-based kNN methods are language-agnostic in mechanism (English-only training) and work cross-lingually (MLS 8 languages: kNN-VC WER 33.9 vs 34.1 FreeVC vs 21.5 topline; EER 25.0 vs 7.7), but degrade badly with short cross-lingual references (FLEURS de↔fr, ~10 s: WER 96.7 %). Seed-VC (Whisper-small encoder, Emilia en/zh/de/fr/ja/ko) and X-VC (en/zh) show en↔zh cross-lingual numbers; CosyVoice 3 (9 languages) and Chatterbox Multilingual (23+) have the widest *claimed* coverage but no published VC metrics.

### Cited Findings
- kNN-VC cross-lingual on Multilingual LibriSpeech (8 European languages, ~9,000 pairs, Whisper-base): topline WER 21.5 / CER 7.1; FreeVC 34.1 / 13.5 / EER 7.7; kNN-VC 33.9 / 13.1 / EER 25.0 — [arXiv 2310.08104 Table 3](https://arxiv.org/abs/2310.08104) [M]. kNN-VC "has only seen English during its design and training" yet converts German→Japanese intelligibly (demo) — [arXiv 2305.18975 §5.1](https://arxiv.org/abs/2305.18975) [R-in-paper].
- MKL-VC vs FACodec vs kNN-VC on FLEURS de↔fr and native-speaker rankings in ar/bn/es/kk/it/sah (MKL ranked first in kk, it, sah; FACodec first in ar, es) — [arXiv 2506.09709 Tables 3–4](https://arxiv.org/abs/2506.09709) [M, 6 raters].
- Palindromic (English-trained) reports WER gains on Dutch, French, German, Italian, Polish, Portuguese, Spanish without fine-tuning — [arXiv 2606.08843 Fig. 2 / Table 2](https://arxiv.org/abs/2606.08843) [M, figure].
- Cross-lingual en→zh / zh→en (Seed-TTS-Eval): Seed-VC small WER 2.82 / SIM 0.52 and 2.36 / 0.42; X-VC 2.67 / 0.52 and 2.15 / 0.49 — [arXiv 2604.12456 Table 4](https://arxiv.org/abs/2604.12456) [M].
- Language coverage claims: OpenVoice v2 6 languages [README](https://github.com/myshell-ai/OpenVoice); CosyVoice 3 9 languages + 18 dialects [README](https://github.com/FunAudioLLM/CosyVoice); Vevo checkpoint en/zh/de/fr/ja/ko [HF card](https://huggingface.co/amphion/Vevo); Chatterbox Multilingual V3 "23+" [README](https://github.com/resemble-ai/chatterbox) [R]. MeanVC's content encoder "only supports Chinese" — [arXiv 2604.12456 §4.3](https://arxiv.org/abs/2604.12456) [R-in-paper]. EZ-VC claims zero-shot cross-lingual including unseen languages — [arXiv 2505.16691](https://arxiv.org/abs/2505.16691) [R-in-paper].

### Inferences
- [I] For SANG's ~15 languages, the safest mechanism is a language-agnostic frame matcher (kNN-VC/MKL-VC) *with a same-language or phonetically rich matching set*; when X's audio is in a different language from the driver, expect accent/phone leakage and higher WER, and prefer MKL-VC/Phoneme-Hallucinator-style densification or a Whisper-encoder DiT (Seed-VC) for that case.
- [I] A small in-house test set (e.g. FLEURS, ~10 utterances × 15 languages × same/cross-language target) with Whisper-large-v3 CER and a speaker verifier is necessary before committing; published evidence covers at most 8 languages per method.

### Gaps
- No per-language results for Indic, Arabic, Southeast-Asian, or tonal languages beyond zh for any shortlisted VC (except MKL-VC's 6-rater ranking).

## Q7. Compute on a single GPU

### Takeaway
All shortlisted methods run offline on one consumer GPU. Measured RTFs: X-VC 0.014, Seed-VC tiny 0.069 and small 0.161 (RTX 3090), StableVC 0.146, SEF-VC 0.168, DDDM-VC 0.287, NS2VC 0.337, AR LM-VC 3.891 / VALL-E-VC 3.944 (RTX 3090); MeanVC 0.136 on one CPU core; kNN-VC "faster than real-time" on an 8 GB GPU with 8 min reference. Adaptation costs: Seed-VC fine-tune ≥2 min on a T4 (README), Phoneme Hallucinator training 6.5 h on an RTX 4090 (one-off, speaker-independent), RVC per-speaker training undocumented.

### Cited Findings
- RTFs (RTX 3090): Seed-VC small 0.161, tiny 0.069, MeanVC 0.094 (chunkwise), X-VC 0.014 — [arXiv 2604.12456 Table 3](https://arxiv.org/abs/2604.12456) [M]; StableVC 0.146, SEF-VC 0.168, DDDM-VC 0.287, NS2VC 0.337, StyleVC 0.075, LM-VC 3.891, VALL-E-VC 3.944 — [arXiv 2412.04724 Table 1](https://arxiv.org/abs/2412.04724) [M].

- kNN-VC real-time on 8 GB GPU with 8 min matching set — [arXiv 2305.18975](https://arxiv.org/abs/2305.18975) [M]. Phoneme Hallucinator: 1.48 s to generate 30 k vectors on RTX 4090 — [arXiv 2308.06382](https://arxiv.org/abs/2308.06382) [M].
- Seed-VC real-time (tiny) on RTX 3060 laptop: ~300 ms algorithm + ~100 ms device latency — [README](https://github.com/Plachtaa/seed-vc) [R]. StyleStream streaming end-to-end latency 1,012.7 ms on RTX A6000 — [arXiv 2602.20113 §6.2.1](https://arxiv.org/abs/2602.20113) [M]. RT-VC 61.4 ms CPU latency — [arXiv 2506.10289](https://arxiv.org/abs/2506.10289) [M].

### Inferences
- [I] kNN search cost grows linearly with matching-set size (≈3,000 frames per minute); for hours of target audio use FAISS (GPU flat or IVF) or cluster the matching set; this is the only scaling cost of the kNN route.
- [I] Offline SANG rendering is not RTF-bound; the binding constraints are licence and timing, not speed.

### Gaps
- No RTF measured for kNN-VC, OpenVoice v2, CosyVoice VC, Chatterbox VC or Vevo-Timbre in a common setting.

## Q9. Preparing the target person's audio (denoising, VAD, diarization, speaker verification) and how much data quality matters

### Takeaway
Target-audio quality matters more for retrieval methods than for zero-shot DiTs: kNN-VC and RVC literally re-emit (or are trained on) the target's frames, so noise, reverb and other speakers in the matching set become output artifacts; zero-shot models degrade mostly on noisy *source* audio (Seed-VC CER 5.16 → 12.45). Standard permissive tooling exists: Silero VAD, pyannote diarization, an ECAPA/WavLM speaker verifier to reject non-X segments, DeepFilterNet3 or Resemble-Enhance for denoising/bandwidth extension, Demucs for music/vocal separation.

### Cited Findings
- Noise sensitivity: Seed-VC CER 5.16 (clean) → 12.45 (noisy source), REF-VC 5.34 → 8.03 — [arXiv 2508.04996 Table I](https://arxiv.org/abs/2508.04996) [M]; MeanVC CER 3.33 (clean) → 12.84 (noisy) — [arXiv 2510.08392 Table 2](https://arxiv.org/abs/2510.08392) [M]; MeanVC's original timbre encoder was "sensitive to reference audio quality" — [MeanVC 2 abstract](https://arxiv.org/abs/2606.09050) [R-in-paper].
- REF-VC ablation: without random erasing, generated audio "exhibit[s] noticeable background noise" copied from the input — [arXiv 2508.04996 §IV-C](https://arxiv.org/abs/2508.04996) [M, spectrogram figure].
- RVC: training data should be ">=10min low noise speech"; noisy data warrants only 20–30 epochs — [README](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/README.en.md), [FAQ](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/faq_en.md) [R]. GenVC: adding "larger but lower-quality datasets can negatively affect conversion quality" — [arXiv 2502.04519](https://arxiv.org/abs/2502.04519) [M]. StableVC and X-VC filter training data by DNSMOS (StableVC: 60 k h → 20 k h; X-VC: DNSMOS > 3.45) — [arXiv 2412.04724](https://arxiv.org/abs/2412.04724), [arXiv 2604.12456](https://arxiv.org/abs/2604.12456) [R-in-paper].
- kNN-VC with stuttered reference audio copies disfluent units into output (lower intelligibility) — [arXiv 2310.08104](https://arxiv.org/abs/2310.08104) [M].
- Tools: Resemble-Enhance = "a denoiser, which separates speech from a noisy audio, and an enhancer, which ... restor[es] audio distortions and extending the audio bandwidth", 44.1 kHz, MIT — [resemble-ai/resemble-enhance](https://github.com/resemble-ai/resemble-enhance) [R]; DeepFilterNet3 48 kHz full-band, real-time, MIT/Apache-2.0 dual licence — [Rikorose/DeepFilterNet](https://github.com/Rikorose/DeepFilterNet) [R]; Demucs (MIT, archived) — [facebookresearch/demucs](https://github.com/facebookresearch/demucs) [R]; Silero VAD (MIT) — [snakers4/silero-vad](https://github.com/snakers4/silero-vad) [R]; pyannote-audio (MIT) — [pyannote/pyannote-audio](https://github.com/pyannote/pyannote-audio) [R].

### Inferences
- [I] Recommended target-audio pipeline for SANG: (1) Demucs vocal separation if music present; (2) Silero VAD, drop segments <1 s; (3) pyannote diarization + speaker-verification cosine to a user-confirmed X enrollment clip (reject below a threshold calibrated on the verifier, e.g. top-scoring cluster only); (4) light denoise (DeepFilterNet3; avoid strong generative enhancement on the *matching set* because generative enhancers can alter timbre); (5) loudness-normalise; (6) DNSMOS/UTMOS gate (e.g. keep DNSMOS OVRL ≥ ~3.0–3.4, mirroring training-data filters above); (7) resample to 16 kHz for WavLM.
- [I] For kNN-VC, prefer fewer, clean, emotionally varied minutes over many noisy minutes: noisy frames will be retrieved for noisy-looking source frames.
- [I] If output fidelity (16 kHz kNN-VC vocoder) is insufficient, apply bandwidth extension (e.g. Resemble-Enhance's enhancer) to the *converted* audio — frame-preserving, so timing is unaffected — and A/B for timbre drift.

### Gaps
- No controlled study found quantifying kNN-VC quality vs matching-set SNR/reverb, or the effect of generative enhancement of reference audio on speaker similarity.

## Q10. Responsible use: consent, watermarking, deepfake detection (design requirements)

### Takeaway
SANG will generate a real person's face and voice, so it falls under deepfake disclosure rules: the EU AI Act Art. 50 (applicable from 2 Aug 2026) requires providers to mark synthetic audio in a machine-readable, detectable way and deployers to disclose deepfakes. Open watermarkers exist (AudioSeal MIT: sample-level localisation, IoU 0.99 vs WavMark 0.35 for 1 s of edited speech; WavMark MIT: 32 bits/s, BER 0.48 %), and Chatterbox VC applies a Perth watermark by default. Post-hoc detection is fragile (OT post-processing can make spoofs pass as bona fide), so consent + watermarking should be primary controls.

### Cited Findings
- EU AI Act Art. 50 applies from 2 August 2026; providers of systems generating synthetic audio must ensure outputs are "marked in a machine-readable format and detectable as artificially generated"; deployers of deepfake audio/video must disclose it — [artificialintelligenceact.eu Art. 50](https://artificialintelligenceact.eu/article/50/); [EC guidelines page](https://digital-strategy.ec.europa.eu/en/policies/guidelines-ai-transparency-obligations) [R, legal text/official guidance].
- AudioSeal (arXiv 2401.17264, MIT): localisation IoU 0.99 vs WavMark 0.35 when one second of speech is AI-manipulated; sample-level (1/16 k s) resolution; generation 14× and detection up to 485× faster than WavMark; quality SI-SNR 26.00 / PESQ 4.470 / STOI 0.997 / ViSQOL 4.829 / MUSHRA 77.07±6.35 vs WavMark 38.25 / 4.302 / 0.997 / 4.730 / 71.52±7.18 — [arXiv 2401.17264 Tables 1, Fig. 5–6](https://arxiv.org/abs/2401.17264) [M]; [facebookresearch/audioseal](https://github.com/facebookresearch/audioseal) MIT [R].
- WavMark (arXiv 2308.12770, MIT): "up to 32 bits of watermark within a mere 1-second audio snippet"; average BER 0.48 % across ten common attacks for 10–20 s hosts — [abstract](https://arxiv.org/abs/2308.12770) [M]; [wavmark/wavmark](https://github.com/wavmark/wavmark) [R].
- Chatterbox: every output carries Perth watermarks said to "survive MP3 compression, audio editing" with "nearly 100% detection accuracy" — [README](https://github.com/resemble-ai/chatterbox) [R, vendor claim]; VC path applies `watermarker.apply_watermark` — [vc.py](https://github.com/resemble-ai/chatterbox/blob/master/src/chatterbox/vc.py) [R].
- Detection fragility: discrete-OT post-processing "can transform spoofed speech into samples that are misclassified as bona fide by a state-of-the-art spoofing detector" — [kDOT, arXiv 2505.04382](https://arxiv.org/abs/2505.04382) [M]. RVCBench evaluates "deepfake detectability" of 18 open-source cloning models and reports "detector-facing separability" vulnerabilities — [arXiv 2602.00443](https://arxiv.org/abs/2602.00443) [M, abstract].
- Frame-synchronous VC leaks the *source* speaker's prosody (kNN-VC anonymisation EER only 7.95 %) — relevant if the driving speaker needs privacy — [arXiv 2409.08913](https://arxiv.org/abs/2409.08913) [M].

### Inferences
- [I] Design requirements: (a) explicit, logged consent from person X for both face and voice, with a live "voice-captcha" (X reads a random phrase; verify speaker match to uploaded voice data) before enabling voice conversion; (b) refuse conversion when the uploaded "X audio" fails speaker verification against the consent recording; (c) watermark every converted waveform (AudioSeal, embedding a job/model ID) *after* all post-processing and before muxing into video; (d) add visible/audible disclosure per Art. 50 for published outputs; (e) keep an internal detector and provenance log (C2PA-style manifest for the video).
- [I] Watermark after VC and after any enhancement so it is not stripped; verify it survives AAC/Opus encoding used for the talking-head video.

### Gaps
- Robustness of AudioSeal/Perth to the specific SANG export chain (AAC in MP4, loudness normalisation) not measured; legal requirements outside the EU (US state laws, India, China) not researched here.

## Q11. Recommendation: which 1–2 VC methods should SANG adopt?

### Takeaway
**Primary: a kNN-VC-family converter on WavLM-Large layer 6** (kNN-VC with prematched HiFi-GAN; MIT) — it is training-free, frame-synchronous on exactly SANG's 50 Hz WavLM grid, preserves source prosody/emotion, and is the only method with documented monotonic improvement as more clean target audio is supplied (plateau ~5 min, best-in-class speaker similarity: EER 37.15 % at ~8 min). Cover its short-reference weakness with matching-set densification (Phoneme Hallucinator or MKL-VC) below ~30 s. **Secondary: a duration-preserving zero-shot flow/DiT model** for 3–30 s references, cross-lingual cases, and higher sample rate — Seed-VC v1 (`length_adjust=1.0`, `convert-style=false`; optional 1-utterance/100-step fine-tuning), or, if GPL-3.0/archival is unacceptable, a permissive alternative (Chatterbox VC with built-in watermark, CosyVoice-300M VC, or X-VC for en/zh) after an in-house timing/quality check. Avoid AR/duration-regenerating modes (Vevo-Voice, Seed-VC v2 `convert-style`, GenVC, StableVC, R-VC) in the lip-synced path.

### Cited Findings
- kNN-VC: frame-level WavLM-L6 (20 ms) conversion; Table 1 WER 7.36 / EER 37.15 / MOS 4.03 at ~8 min vs FreeVC 7.61 / 8.97 / 4.07; plateau ~5 min; poor below 30 s — [arXiv 2305.18975](https://arxiv.org/abs/2305.18975) [M]; MIT — [repo](https://github.com/bshall/knn-vc) [R].
- Short-reference fixes: Phoneme Hallucinator (3 s) WER 5.10 / EER 44.62 / MOS 4.02 — [arXiv 2308.06382](https://arxiv.org/abs/2308.06382) [M]; MKL-VC (one 5–10 s utterance, training-free) WER 8.131 — [arXiv 2506.09709](https://arxiv.org/abs/2506.09709) [M].
- Crossover evidence: at 30–60 s kNN-VC ≈ Seed-VC on SIM (0.617/0.631 vs 0.622/0.630) with slightly higher WER (4.2/4.6 % vs 2.6/3.3 %); at 3–10 s Seed-VC far better (kNN-VC WER 43.0/11.5 %) — [arXiv 2606.08843 Table 1](https://arxiv.org/abs/2606.08843) [M].
- Emotion: kNN-VC emotion UAR 56.70 % vs 30.35 % for ASR→TTS — [arXiv 2409.08913](https://arxiv.org/abs/2409.08913) [M].
- Seed-VC: SECS 0.8676 / WER 11.99 vs OpenVoice 0.7547 / 15.46 and CosyVoice 0.8440 / 18.98 — [arXiv 2411.09943](https://arxiv.org/abs/2411.09943) [M]; length_adjust default 1.0; fine-tune from 1 utterance, 100 steps, ~2 min on T4; GPL-3.0; archived — [README](https://github.com/Plachtaa/seed-vc) [R]. Seed-VC tends to follow reference prosody — [arXiv 2508.04996](https://arxiv.org/abs/2508.04996) [M, ABX].

### Inferences
- [I] Proposed SANG flow: (1) compute WavLM-Large once on the driving audio (already needed for the face); (2) if no X audio → keep driving voice (or consented stock voice); (3) if X audio: clean/verify (Q9) and store its layer-6 frames as X's growing matching set; (4) route by clean duration: <10 s → Seed-VC-class zero-shot (or Phoneme Hallucinator/MKL-VC), 10–30 s → run both and pick by automatic score (speaker-verifier cosine to X, Whisper CER vs driving transcript, UTMOS), ≥30 s → kNN-VC (k=4; ~8–20 once ≥10 min); (5) optional bandwidth extension; (6) AudioSeal watermark; (7) drive the face from the *source* WavLM features (timing-identical) or from the converted audio — both are frame-aligned for kNN-VC; for the DiT path, verify ≤1-frame DTW deviation before using converted audio for motion.
- [I] Upgrade path as data grows beyond ~10–30 min: A/B a fine-tuned model (Seed-VC fine-tune, or RVC with index_rate≈0.5–1.0, MIT) against kNN-VC on held-out clips; keep whichever wins on speaker-verifier score and CER, since no published evidence says when fine-tuning overtakes kNN-VC.
- [I] Worth piloting in 2026: Palindromic VC (WavLM-L6, kNN-derived, multilingual WER gains, SIM 0.71 from 10 s) and kNN-FM-VC — same frame grid as kNN-VC with better short-reference behaviour — once code/licence are confirmed.

### Gaps
- No head-to-head of kNN-VC vs Seed-VC on SANG-like material (emotional, multilingual, video-sourced audio) exists; an in-house evaluation (15 languages × {3 s, 30 s, 5 min} of X audio × {same, cross} language) is required before final selection.
- Licence of Emilia-trained checkpoints (Seed-VC, X-VC) for commercial use is unverified.
